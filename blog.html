Building a Railway Reservation System

A look at the problem, design decisions, implementation and lessons from developing a menu-driven railway reservation application in C++.

← Back to project portfolio
By Aman·BCA Data Science·Object-Oriented Programming

1. Why this project?

Railway reservation involves several connected tasks: checking trains, confirming seat availability, recording passenger details, issuing a ticket and processing cancellations. When these activities are handled manually, they can take time and may lead to record-keeping or calculation errors.

I developed this project to create a simplified computer-based version of these basic reservation-counter activities and to apply C++ programming concepts to a practical problem.

2. What does the system do?

The application provides a numbered console menu. Passengers can view available trains, book a ticket, cancel a ticket and check its status using a PNR number. Administrator options allow a new train to be added and all booking records to be viewed.

Seven menu choices: View Trains · Book Ticket · Cancel Ticket · Check PNR Status · Add Train · View All Bookings · Exit.

3. Designing the program

The design is organised around three classes. Train stores train number, name, source, destination, seat count and fare. Ticket stores PNR, passenger details, train number, number of seats, amount and booking status. ReservationSystem manages the train and ticket collections and performs the main operations.

STL vectors hold train and ticket records while the program is running. The functions in the reservation controller load, save, search, book and cancel records.

4. Saving data with file handling

The project uses two plain-text files: trains.txt and tickets.txt. Records are written as lines with fields separated by a pipe character (|). When the application starts, it loads existing records into vectors. After a booking, cancellation or train addition, the updated records are saved again.

5. Booking, fare and cancellation rules

During booking, the system checks whether the selected train exists and whether the requested number of seats is available. It calculates the fare and generates the next PNR, beginning with 1001. For passengers aged 60 or above, the project applies a 40% concession.

When a confirmed ticket is cancelled, the booked seats are returned to the train's available-seat count. The refund is calculated as 80% of the ticket amount, with a 20% cancellation charge. A ticket that is already cancelled cannot be cancelled again.

6. Testing the application

The project report records tests for normal booking, senior-citizen concession, invalid train numbers, requests for too many or zero seats, cancellation, repeated cancellation, incorrect PNRs, duplicate train numbers, non-numeric input and data persistence after restarting the program.

The report states that the listed test cases passed after correcting an input-handling issue involving non-numeric menu input.

7. What I learned

  • How to divide a problem into classes and member functions.
  • How vectors can store collections of objects dynamically.
  • How file streams can preserve records between program runs.
  • How to validate user input and handle invalid operations.
  • How to translate business rules into program logic.

8. Current limitations and future improvements

The current version is console-based, has no user login, does not allocate specific berth numbers or travel dates, and uses text files rather than a database. The project report identifies possible future improvements such as login, journey dates, berth allocation, waiting list/RAC, database storage, a graphical or web interface, and online payment or ticket notifications.

9. Conclusion

Developing the Railway Reservation System helped me connect C++ concepts with a familiar real-world process. The application covers the basic workflow of viewing trains, booking and cancelling tickets, checking PNR status and managing train records. It also provided practical experience in designing, implementing and testing a small software system.
